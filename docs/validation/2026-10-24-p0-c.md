## 2. Inputs

- **Tool.** `tools/p0c.py` has not changed since the smoke commit `f488ee0`. The branch head is `5685c91` (code `7c770a1b`). Rules: spec §9.4, r7 §4, D-18, D-46, PF-38 to PF-42, PF-40 extended, A-6 and A-7. Revised on 2026-10-26 after the final review (`ab3219e`, `b7e6513`): the tool refuses an `<OUT>` made for another board or other `new` options, and C3 treats E_PORT_SPANS like E_PORT_BOX.
- **What the owner supplies.** A copy of the private board file, outside every git work tree. The start and end pads, given as REF.PAD, and f0. Optionally: the harmonics, the lid height and the stackup. Also optional: a folder of the owner's own S2P files, named `<REF>.series.s2p` or `<REF>.shunt.s2p`.
- **What the owner runs**, from the repo root with the dev venv, on an idle PC:
  `.venv\Scripts\python.exe tools\p0c.py --board <BOARD-COPY> --start <REF.PAD> --end <REF.PAD> --f0 <F> [--harmonics N] [--lid-height MM] [--stackup NAME] --out <OUT> [--preset strict] [--steps C0,C1,...] [--s2p <DIR>]`
- **Safety.** The tool exits 2, prints one line and writes nothing if `--board` or `--out` lies inside a git work tree, if `--board` is not a file, or if `<OUT>` was made for another board or other `new` options (it keeps the board's sha256 and those options in `<OUT>/inputs.json`). Otherwise it:
  - takes `<OUT>/harness.lock`;
  - copies the board into `<OUT>/board`, so the original is never touched;
  - points `LOCALAPPDATA` and `XDG_DATA_HOME` at `<OUT>/data` for every CLI child (D-7), so C0's first `cost` calibrates that fresh data folder (PF-42, PF-56).
- **How a run proceeds.** The steps run in `STEPS` order. By default that is C0 to C6, plus S2P when `--s2p` is given. A step that raises is printed and skipped, and the tool then exits 1. The reports are written at the end of every invocation that is not stopped.
- **Resuming.** A step whose record holds the same step key and code id is not run again; a code change runs it again. The step key is the model key, plus the preset for C1; C1's run folder for C2; C1's run folder plus each file's name and sha256 for S2P. The reports refuse records made by two product codes, so run every step on one commit. A rerun into the same `<OUT>` needs the same board bytes and `new` options; for another board or options, use a fresh `<OUT>`. A file named `STOP` in `<OUT>` ends the run before the next step, without writing the reports.

## 5. Stated limits and deviations

- **Risk: port-box refusals (A-6, E_PORT_BOX).**
  - *The rule.* `place()` builds each lumped box across the copper-free gap between its two pads. It refuses when no mesh line lies inside a pad, when no copper-free line lies between the pads, or when a cap touches other copper.
  - *Where it may fire.* On a private board, the base itself may be refused for a port or a part. Likely cases: dense QFN pads, a reference pad across other pins or a pour, or small pads at n = 2.
  - *What happens then.* Every step fails. The tool exits 1 with nothing measured.
  - *Remedies.* The message names them: another mesh.n, larger pads, or clearing copper from between the pads. `preview` builds the same model, so it refuses too. These are copper or mesh changes, and each must be recorded; a copper change is a board edit, which needs a fresh `<OUT>`.
  - *The catch with mesh.n 3.* `p0c.py` has no option for mesh.n, so raising it means editing the base project in `<OUT>`. Edit the base after `--steps C0` alone, before any other step runs: a step's copy of the base is made only when it is missing, so a copy left by a refused run keeps the old mesh and the refusal repeats. Otherwise delete the copies under `<OUT>/projects` (C3 to C6) that a refused run left, or start again in a fresh `<OUT>`. C4a then sets mesh.n 3 on a base already at n = 3, so criterion 4's mesh half would no longer test anything.
- **C3 coverage.** C3 may measure fewer ports than it moved (the cost of the ruling above).
- **verify's known differences** (verify's one-cell L strips, A-7's fill fringe) were pre-registered on lpf915 only. On a private board, a criterion-1 result near its limit must be read against them.
- **C1's preset.** C1 must run at Normal or Strict (Strict is the default), or c2 to c4 read None.
- **"Also" item: the research's real-board case.** It has no key of its own in `p0c.py`. Its stand-in is the base replayed at Normal. C1's job residuals (at C1's own preset) are in the private report. C_box stays in C1's project results, where criterion 2 uses it; the report does not print it.
- **Throughput and RAM.** The parallel throughput comes from the calibration entry and each job's openEMS speed. A step that ran while other work was on the machine is flagged as loaded (PF-9). RAM is the system-wide free RAM. The per-preset wall times use a round model of the pool from the progress events, with job setup not counted.
