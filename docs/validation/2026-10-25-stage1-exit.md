### P0-C procedure, on one page (D-46, condensed from `2026-10-24-p0-c.md`)

**Status:** recorded **"do not start"** (D-45). It runs only if the owner overrides that, and only after the Stage 2 fixes in section 7 if `RETUNE_VALIDATED` is ever to flip. No P0-C number is committed, and no board number appears here.

- **The owner supplies:** a copy of the private board outside every git work tree; start and end pads as REF.PAD; f0. Optional: harmonics, lid height, stackup, and a folder of their own `<REF>.series.s2p` / `<REF>.shunt.s2p` files.
- **Command** (repo root, dev venv, idle PC): `tools\p0c.py --board <BOARD-COPY> --start <REF.PAD> --end <REF.PAD> --f0 <F> [--harmonics N] [--lid-height MM] [--stackup NAME] --out <OUT> [--preset strict] [--steps C0,...] [--s2p <DIR>]`. Run `--steps C0` first. It prints the cost and any E_PORT_BOX before the long steps. Use a fresh `<OUT>` on the final code: the smoke's records carry another code id.
- **Safety:** the tool exits 2 and writes nothing if `--board` or `--out` lies inside a git work tree. It copies the board into `<OUT>/board`, points LOCALAPPDATA and XDG_DATA_HOME at `<OUT>/data`, and takes `<OUT>/harness.lock`. A `STOP` file ends the run before the next step. Steps resume by step key and code id.

| C0 | base | `cost` | cells, dt, predicted times |
| C1 | base at Strict (default) | `run` | base S; the per-preset replay, speed and RAM |

| C3 | each port's reference moved to its next-best one | `run` | c3 |
